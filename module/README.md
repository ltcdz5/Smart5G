# Smart 5G Switch

一个自动切换数据网络来省电的 KernelSU 模块。

**作者**：ltcdz5 ｜ **版本**：v1.0

---

## 它是干嘛的

手机在 5G 信号弱的时候，网络速度可能还不如 4G，耗电反而更高——因为它要不停地搜网、重连。

这个模块会在合适的时候自动帮你切换到 4G，条件恢复了再切回 5G。**切换过程没有弹窗，你基本感觉不到。**

什么时候切到 4G：

- 手机发烫了（超过 40℃）
- 电量太低了（20% 以下，充电时除外）
- 5G 信号变差了

什么时候切回 5G：

- 温度降下来了
- 电充上来了
- 信号确实变好了

---

## 怎么用

**装好后什么都不用做**，它自己会工作。

想调设置的话，打开 KernelSU 管理器 → 模块 → Smart 5G Switch → 点"打开"，会看到一个界面：

- 上面显示当前是 4G 还是 5G、温度、电量
- 中间可以改各个阈值
- 下面能看最近的切换记录
- 右上角按钮切换白天/夜间模式
- 改完点底部的"保存并重启守护"

如果不想开界面，也可以直接改配置文件：

```
/data/adb/smart5g.conf
```

## 几个设置的意思

| 设置 | 默认 | 说明 |
|---|---|---|
| 高温阈值 | 40℃ | 手机热到这个温度就切 4G |
| 降温阈值 | 36℃ | 不充电时降到这个温度以下才回 5G |
| 充电时高温阈值 | 45℃ | 充电中电池本来就会热，超过这个温度才按高温切 4G |
| 充电时降温阈值 | 42℃ | 充电中降到这个温度以下即回 5G（否则充电时永远降不到 36℃） |
| 弱信号阈值 | -100 dBm | 信号差到这个程度就切 4G |
| 信号好阈值 | -88 dBm | 信号好到这个程度才回 5G |
| 低电量阈值 | 20% | 电量低于这个就切 4G；回切需高于 23% |
| 检测间隔 | 120 秒 | 多久检查一次 |
| 切换冷却 | 300 秒 | 两次切换之间至少隔这么久 |
| 探测间隔 | 300 秒 | 因弱信号回落 4G 后，多久探测一次 5G |
| 探测时长 | 20 秒 | 探测时临时放开 5G 多久 |
| n78 聚合加严 | 开 | n78 频段下弱信号阈值 +3 dB |
| 充电时跳过切换 | 关 | 充电时不因弱信号回落（低电量判定本来就排除充电） |
| 允许飞行模式兜底 | 开 | 重新注册 5G 失败时用飞行模式重试（约断网 10 秒；通话中永不执行，失败后间隔翻倍） |

**小提示**：「信号好阈值」和「弱信号阈值」之间的差距最好有 8 dB 以上。差距太小的话，会因为信号轻微波动而反复切换。
默认值 -100 / -88 是 12 dB；开启 n78 加严后弱信号阈值变 -97，仍有 9 dB，符合这个要求。

## 常见问题

**会不会影响网速？**

只在你本来信号就不好（或手机很热、电量很低）的时候才切 4G。正常用 5G 的时候不受影响。

**切换的时候有什么提示吗？**

没有。它用的是系统接口，和你在设置里手动切换网络模式效果一样，只是静默执行，不会弹提示框。

**费电吗？**

几乎不费电。实测内存占用 1.8 MB，平时处于休眠状态，每 2 分钟检查一次。平均 CPU 占用基本为 0。

**能关掉吗？**

能。把配置里的 `netmode` 改成 `5g` 就是强制 5G 不自动切；或者直接卸载模块。

**切换失败怎么办？**

如果系统不支持这种切换方式，日志里会提示"连续 3 次切换失败"。看日志：

```
/data/adb/smart5g.log
```

## KernelSU 越狱（late-load）模式

不需要额外设置，装好模块后越狱完成即自动运行。

依据官方源码 `userspace/ksud/src/late_load.rs`，越狱加载内核模块后依次执行：

```
late-load → post-mount → service → boot-completed
```

模块的 `service.sh` 在 **service 阶段**执行，所以守护会自动起来。

注意两点：

- 越狱本身重启失效，需要重新越狱；模块文件在 `/data/adb/modules/` 不会丢。
- 在已经正常开机过、KSU 早已启动的系统上执行 `ksud services`，会提示
  "services already started, skipping" —— 这是内核侧幂等标记，属正常现象，不是故障。

如果你用的越狱工具只调用 `ksud post-fs-data` 而不走 late-load 流程，
模块里的 `post-fs-data.sh` 会在系统已启动完成时兜底拉起守护。

## 卡在 4G 回不去怎么办

### 为什么会卡住

模块把 5G 关掉再放开之后，手机不一定马上重新注册 5G。这不是模块忘了切回来——
而是 modem 的状态机问题：**网络类型掩码已经允许 5G，但射频那边还挂在 LTE 上**。

实测这台机器上三种唤醒手段的表现：

| 手段 | 效果 |
|---|---|
| `svc data disable/enable`（关开移动数据） | 基本无效 |
| 掩码抖动（关 5G 三秒再放开） | 时灵时不灵 |
| 飞行模式 | 稳定有效，但会断网约 10 秒 |

所以模块只能靠飞行模式兜底，这就是为什么会偶尔感觉网络闪一下。

### 模块会自动做什么

1. 放开 5G 后先进入 **90 秒观察期**，期间不碰网络，让 modem 自己完成重新注册
2. 观察期结束还没注册上，才尝试重新注册：先掩码抖动，不行再飞行模式
3. **尝试失败也不回关**，保持允许 5G，按 300 → 600 → 1200 → 2400 → 3600 秒退避再试
4. 通话中一律不动，挂断后自动恢复

早期版本是「等 18 秒没注册就回关 4G」，而 modem 重新扫 NR 需要几十秒，
等于自己把重注册打断，所以老是卡住。这个缺陷已经改掉。

### 想更快回到 5G，调这几个

| 现象 | 调什么 | 建议 |
|---|---|---|
| 等太久才尝试 | `probe_interval` | 300 → 180 |
| 明明有 5G 却不回 | `sig_good` | 别设太高，-88 ~ -90 合适；设成 -80 基本回不来 |
| 太容易掉到 4G | `temp_high` 40 → 42；或关掉 `n78_aggr` | |
| 冷却期太长 | `cooldown` 300 → 180 | |
| 完全不自愈 | `refresh_airplane` 必须是 1 | 默认已开，别关 |

### 手动救一次

三种任选：

- WebUI 里点「重新注册 5G」按钮
- 命令行：`su -c "sh /data/adb/modules/smart5g/bin/netmode.sh refresh"`
- 手动开关一次飞行模式（最直接）

### 什么时候不是模块的问题

- **该位置确实没有 5G**：拿别的手机对比一下
- **双卡限制**：部分机型或套餐只允许一张卡驻留 5G
- **运营商限制**：副卡、物联网卡、部分定向套餐不给 5G SA

判断方法：

```sh
su -c "sh /data/adb/modules/smart5g/bin/netmode.sh status"
```

看数据卡那行是不是「NR允许」。

- 显示 **NR允许** 但一直是 LTE → 点一次「重新注册 5G」
- 重新注册也失败 → 大概率是覆盖或运营商限制，模块无能为力
- 显示 **NR关闭** → 说明是模块主动回落的，等条件恢复即可，或点「强制 5G」

## 卸载

在 KernelSU 管理器里卸载，重启就好。

配置文件 `/data/adb/smart5g.conf` 会自动保留，想彻底清干净就手动删掉它和 `/data/adb/smart5g.log`。
